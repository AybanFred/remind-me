THE PHASES
-----------

PHASE 2 — Task list (CRUD)
Build the core tasks feature on top of the existing `tasks` table
(columns: id, user_id, title, notes, category, status, due_at, position,
completed_at, created_at; category is one of upskilling/job_hunt/daily;
status is one of todo/doing/done).
- A form to add a task (title, notes, category, optional due date)
- A list view showing all my tasks
- Edit a task in place
- Mark a task complete (sets status='done' and completed_at)
- Delete a task
- Filter the list by category (upskilling / job_hunt / daily / all)
All reads/writes should go through the Supabase client and respect the
logged-in user (RLS already handles this server-side).

PHASE 3 — Kanban board
A board view with three columns: To Do, Doing, Done, driven by the same
`tasks` table (status field). Use vue-draggable-plus so I can drag cards
between columns and reorder within a column. On drop, update both `status`
and `position` in Supabase so the order persists on reload.

PHASE 4 — Focus timer (Pomodoro)
A Pomodoro timer: 25 minutes focus / 5 minutes break, start/pause/reset.
Let me optionally link a session to a specific task. When a focus session
ends (or I stop it early), save a row to a new `focus_sessions` table
(columns: id, user_id, task_id nullable, started_at, minutes_focused).
Give me the SQL to create this table with RLS matching the `tasks` table.

PHASE 5 — Dashboard
A dashboard page with:
- Current daily streak (consecutive days with at least one completed task
  or focus session)
- Tasks completed this week, broken down by category
- A chart (Chart.js) of focus hours per day over the last 7 days
Pull everything from the real `tasks` and `focus_sessions` tables — no
placeholder/fake data.

PHASE 6 — Reminders
Browser notifications (Notification API) for tasks with a due_at coming up
or overdue. Ask for notification permission at an appropriate point in the
UI, not immediately on page load. Note for me in your explanation: this only
works while the app is open in a tab; true "closed app" push notifications
are a later upgrade (web push), not part of this phase.

PHASE 7 — AI coach
Using the Claude API (called from a Supabase Edge Function so my API key
never reaches the browser), add:
- "Break this goal into tasks": I type a goal, it returns a list of
  suggested tasks (with category guesses) that I can review and add in bulk
- A daily plan suggestion based on my open tasks and due dates
- Short motivational check-in messages based on my real stats (streak,
  completed vs overdue tasks) — not generic canned text
Walk me through creating the Edge Function, setting the Claude API key as a
Supabase secret, and calling it from the frontend.

PHASE 8 — PWA + deploy
- Configure vite-plugin-pwa so the app is installable on my phone (manifest,

- Push the project to GitHub (help me write a clean README describing the

- Deploy to Vercel connected to the GitHub repo
- Update the Supabase Site URL / Redirect URLs and Google OAuth redirect URI
